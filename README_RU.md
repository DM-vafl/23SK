# 23СК — бесплатная облачная версия (GitHub Actions + Pages)

Эта версия переносит мониторинг с Windows-ПК в GitHub Actions, а веб-панель — на GitHub Pages.

## Что работает

- GitHub Actions запускает проверку публичной папки Яндекс Диска каждые 5 минут (cron `2-59/5`).
- При изменении последнего DOCX файл скачивается и читается; для 23СК публикуются найденные строки либо сообщение «На эту дату замен нет».
- При изменении документа бот отправляет уведомления в чаты, заданные в GitHub Secret `TELEGRAM_CHAT_IDS`.
- `/start`, `/help`, `/id`, `/today`, `/tomorrow`, `/week` обрабатываются при очередном запуске workflow. Команды могут отвечать с задержкой до следующего запуска.
- GitHub Pages отдаёт статический сайт; галерея Маши и сердечки работают в браузере без сервера.

## Ограничения и приватность — прочитай до публикации

1. Для бесплатного GitHub Pages на GitHub Free репозиторий должен быть **публичным**. Публичными будут исходный код, три фотографии в `site/masha_photos/`, `site/data.json` с опубликованными заменами и сам сайт. Ссылка не является приватной.
2. Никогда не добавляй Telegram-токен, `.env`, базу `data.sqlite3`, пароли или личные данные в репозиторий. Токен хранится только в GitHub Secrets.
3. GitHub Actions scheduled workflows разрешают расписание раз в 5 минут, но GitHub предупреждает, что запуск иногда задерживается или пропускается при высокой нагрузке. Это не гарантированный таймер и не SLA.
4. Публичные scheduled workflows автоматически отключаются после 60 дней без активности репозитория. Иногда нужно внести обычное изменение в репозиторий и проверить Actions.
5. Этот парсер ищет строки, где прямо указана группа 23СК. Если таблицы колледжа устроены иначе, потребуется адаптация.
6. Команды `/today`, `/tomorrow`, `/week` пока показывают последний опубликованный документ, а не вычисляют календарный день/неделю по структуре расписания.
7. GitHub Pages — статический сайт. FastAPI, SQLite и постоянно работающий процесс на Pages не запускаются. Обновления сайта публикуются JSON-файлом.
8. Первый запуск создаёт исходную точку и публикует последний документ без рассылки всех старых файлов. Новые изменения отправляются в настроенные чаты.

## Шаги развёртывания

### 1. Создай публичный пустой репозиторий

Открой https://github.com/new и создай репозиторий:
- Owner: `DM-vafl`
- Repository name: `23SK`
- Visibility: **Public**
- Не добавляй README, .gitignore или License (они уже есть в этом пакете).

### 2. Установи Git for Windows (если Git ещё не установлен)

https://git-scm.com/download/win

После установки закрой и заново открой Проводник, затем распакуй этот ZIP в отдельную папку, например `C:\23SK_GitHub_Free`.

### 3. Загрузи файлы

Дважды щёлкни `PUBLISH_TO_GITHUB.bat`. Когда скрипт спросит подтверждение, нажми любую клавишу. При первом `git push` откроется окно входа GitHub. Авторизуйся в своём аккаунте `DM-vafl`.

Если репозиторий назвал иначе или использовал другой аккаунт, сначала измени URL `https://github.com/DM-vafl/23SK.git` в `PUBLISH_TO_GITHUB.bat`.

### 4. Добавь GitHub Secrets

В репозитории открой **Settings → Secrets and variables → Actions → New repository secret** и создай:

- `TELEGRAM_BOT_TOKEN` — токен от @BotFather. Вставлять только в GitHub Secrets, не в файлы и не в переписку.
- `TELEGRAM_CHAT_IDS` — один или несколько Telegram chat ID через запятую, например `123456789,-1001234567890`.

Чтобы получить chat ID:
1. Останови локальное окно `run_bot.bat` на старом ПК, чтобы оно не забирало обновления Telegram.
2. В Telegram отправь боту команду `/id`.
3. В папке этого пакета запусти `GET_CHAT_IDS.bat`, введи токен (ввод будет скрыт). Скрипт покажет chat ID последних ожидающих сообщений. Не публикуй вывод с chat ID.
4. Скопируй свой ID в секрет `TELEGRAM_CHAT_IDS`. Дополнительные люди могут написать боту `/id`; добавь их IDs через запятую.

### 5. Включи GitHub Pages

Открой **Settings → Pages → Build and deployment → Source → GitHub Actions**.

### 6. Запусти первое развёртывание

Открой вкладку **Actions → 23SK cloud monitor and Pages → Run workflow → Run workflow**.
Первый запуск проверит Яндекс Диск, запишет текущий документ в `site/data.json` и опубликует сайт. После этого расписание будет проверяться автоматически каждые 5 минут.

Адрес будет вида: `https://DM-vafl.github.io/23SK/`.

## Включение уведомлений другим чатам

- Отправь боту `/id` из нужного чата.
- Получи chat ID через `GET_CHAT_IDS.bat` (локальная команда использует getUpdates; останови другие процессы, которые опрашивают этого бота).
- Добавь ID к значению секрета `TELEGRAM_CHAT_IDS`, разделяя ID запятыми.
- Новые сообщения отправляются только в чаты, перечисленные в этом секрете.

## Возврат на локальную версию

Не удаляй старую папку `C:\23SK` до проверки облачной версии. После успешного запуска GitHub Actions выключи локальные `run_bot.bat`, `run_monitor.bat`, `run_web.bat` и Pinggy/Cloudflare tunnel, чтобы не было двойных уведомлений. Старые файлы останутся резервной копией.
